# stdshader_dx12 — native SM5.1 material shaders for shaderapidx12

`stdshader_dx12.dll` is the material shader DLL the DX12 backend selects (`CHardwareConfigDX12::GetShaderDLLName()`).
It registers the same material names, parameters and combo semantics as the DX9 `stdshader_dx9`, but draws with
precompiled SM5.1 DXBC shaders published as VCS files in `<game>/shaders/vsh`, `<game>/shaders/psh`, and
`<game>/shaders/csh`.

## Layout

| Path | Content |
|---|---|
| `cpp/` | Material C++ (ported from `materialsystem/stdshaders`) and `BaseVSShaderDX12.*` (constant staging, native block selection, command-buffer execution). Hand-maintained. |
| `hlsl/` | Generated native sources `<base>_vs51.fxc` / `<base>_ps51.fxc`; `hlsl/common/` shared headers. **Generated** by `tools/` — never edit by hand. |
| `native_src/` | Hand-authored native-only SM5.1 sources, including compute (`*_cs51.fxc`). These are the single source of truth and are compiled directly; they are never copied into generated `hlsl/`. |
| `manifests/` | Per-slice build manifests (`<source> <vs\|ps\|cs> <logical> <legacy profile> <legacy source>`, where native-only uses `native -`, plus `# pair`, `# noparity`, `# legacy`). Generated by `tools/genmat.py`. |
| `legacy_reference/` | Generated DX9 source copies with shipped combo-directive overrides (`gensource.ABI_PATCHES`). Used only for legacy-backed packer `-dynamic` ABI references; original SDK sources are unchanged. |
| `generated/` | Combo index includes, cbuffer C++ layouts, reflection metadata. Written by `nativeshaderpack_dx12` on every build. |
| `tools/` | Generators: `gencommon.py` (hlsl/common from the DX9 headers), `gensource.py` (per-source conversion + `PATCHES` for shipped-compiler quirks), `genmat.py` + `pairs.py` (pair table → hlsl + manifests), `hlslport.py` (sampler/intrinsic translation), `quickcheck.py` (sampled fxc compile of every source). |
| `vpc/`, `stdshader_dx12.vpc` | DLL project. |

## Naming

Native logicals are `<base>_vs51` / `<base>_ps51`, one per base. Compute logicals are native-only `<base>_cs51` and
are published under `shaders/csh`; they have no DX9 record or fallback. Legacy-backed logicals also name a DX9 record
(`<base>_vs20`, `_ps20b`, `_vs30`, …) used for the combo-ABI reference and fallback record in `shaders/fxc`.
Material C++ uses the `_vs51`/`_ps51` index classes; names that come from VMTs (`screenspace_general`'s `$pixshader`,
`sample4x4`, `floattoscreen`) are mapped with `DX12NativeShaderName()`.

## Build

```bat
cd /d src\materialsystem\stdshaders_dx12\tools
python gencommon.py        :: only when common headers / hlslport change
python genmat.py
python quickcheck.py       :: optional sampled compile check
cd /d src
devtools\bin\buildshaders_dx12.bat -game <gamedir>   :: or -stage <tempdir>
```

`buildshaders_dx12.bat` → `process_shaders.ps1 -Native`: compiles each manifest line with `ShaderCompile2 -ver 51`
(rebuilt from `thirdparty/ShaderCompile2`; bounded memory, memory-aware threading) in a persistent per-logical cache.
Generated `hlsl/` and hand-authored `native_src/` sources are both available to the compiler; native-only lines are
compiled directly and are not copied into generated trees. Legacy-backed lines additionally compile their DX9 source
with `-dynamic` (using `legacy_reference/` overrides where present), then `nativeshaderpack_dx12` validates DXBC,
VCS v6, cbuffer reflection/space-1 rules, and combo ABI only where a legacy reference exists. It owns `shaders/vsh|psh|csh`
entries listed in `shaders/native_dx12_published.txt` and writes `shaders/native_dx12_legacy_names.txt`; nothing is
written under `shaders/fxc`. Build cost depends on the manifest set, folded combo counts and compiler-cache state. Then rebuild
`stdshader_dx12` (it includes `generated/`).

Partial `genmat.py <slice>...` runs retain the first pair-table slice as the unique manifest owner of shared ordinary VS/PS logicals, even when that owner is not regenerated. Other slices keep their parity pair references without redeclaring the shader; this prevents duplicate logicals at publication.

## Runtime contract

- Material constants keep the DX9 register vocabulary and are staged in the DLL; each selected native block is sent
  once per draw through the private space-1 cbuffer bridge (`native_cbuffer_dx12.h`). Engine values (matrices, fog,
  ambient cube, lights, bones) come from the backend's engine blocks.
- Queued client post-processing retains its material references and primes `FindVarFast` tokens on the client
  thread, before render-owner replay. The engine's `FindVar` symbol search uses shared scratch state under a reader
  lock; concurrent searches could intermittently return a dummy var even for a valid `screenspace_general_dx9`
  material. Histogram C0 constants, source retargeting, legacy/native bloom, composite, RCAS and motion-blur tile
  parameters therefore use pre-primed tokens, which revalidate indices after material reload without re-entering
  the symbol search. Material proxy initialization is warmed during main-thread precache. The histogram remains
  the exposure producer; no native replacement bypasses it.
- DX12 keeps the legacy `mat_reducefillrate` setting at 0. `PreferReducedFillrate()` is always false on this backend,
  so Shader Detail Low would reload all materials without selecting cheaper shaders or combos. The client restores
  unsupported nonzero requests immediately, with one console note, before the engine applies a config change; this also
  protects older configs containing `mat_reducefillrate "1"`. The mod's Advanced dialog omits Shader Detail on DX12,
  while DX9 retains the original setting. Native feature-quality controls remain available.
- A legacy-backed native logical whose `shaders/vsh|psh` record is absent resolves to its legacy DX9 record in
  `shaders/fxc` via `native_dx12_legacy_names.txt` and is translated as before.
- Native-only logicals have no legacy name or fallback. Their native VCS must exist at runtime; if it is missing,
  the backend fails the shader load rather than trying `shaders/fxc`.
  SM2/SM3 centroid interpolation is declared in the VCS header (centroid mask), not in the bytecode; the backend
  carries that mask to the legacy translator, matching the native sources' `centroid` inputs.
- `-dx12shaderlog` prints which VCS file each named shader was loaded from.
- `shader_precache <logical> [static] [dynamic] | all` (cheat) validates/reflects published VCS payloads on the render
  thread; it never writes VCS files.
- Legacy VCS centroid masks are carried into deferred translation. SM2 shaders declare centroid TEXCOORDs in
  the VCS header rather than bytecode DCLs; dropping that mask makes MSAA edge inputs differ from native shaders.
- Eligible native mono main views shade the 3D sky after opaque geometry and motion vectors, before GTAO/SSR.
  `ShaderAPIDX12ScreenSpace_003` brackets it with a far-depth LEQUAL stencil mark (`0x40`; PBR validity remains
  `0x80`). Sky draws retain their own depth/blend/fog but can shade only marked pixels; the end marker restores
  those pixels to far depth and removes `0x40`. Main contact/SSR bindings stay neutral during the sky draw.
  Water/fog-volume, reflective-glass, solid-space, stereo, cubemap, intro, Portal and offscreen views retain sky-first ordering.
  On the RTX 4070S at 1080p, paired `d1_trainstation_02` measurements reduced the sky event from 0.380 to 0.061 ms
  in the alley and 0.164 to 0.051 ms in the stairwell. Fixed-exposure, frozen-scene screenshots with GTAO/contact
  shadows enabled matched exactly for the open citadel view; alley/stair residuals were at most 1 code value,
  also present in unchanged-path repeats. SSR's frame-indexed GGX noise has the same A/A and A/B variance;
  SSR remains after the completed sky color and restored main depth. Evidence: `_agent_tools/out/sky_1080*`
  and `sky_exact*` (the latter screenshots predate the harness DPI correction).
- Feature detail sprites (`DX12_DetailShadowLit`) gamma-decode retained vertex illumination once, add runtime
  direct in linear units, then multiply by sRGB-decoded albedo and gamma-to-linear material tint. The lit pass
  uses `TONEMAP_SCALE_LINEAR` and standard sRGB output state; it must not gamma-encode RGB before the linear
  HDR target. Alpha/cutout and shadow-depth behavior are unchanged. The grass-color correction was verified
  on `d1_trainstation_02` in HDR with exit 0 (`_trainstation_grassfix_verification.json`); LDR was not exercised,
  and the screenshot comparison is not a raw-radiance measurement.
- The scene color target is linear FP16 and is gamma-encoded only at presentation, so a draw without sRGB write
  must still store linear values. `Sprite` writes gamma by default (`$nosrgb`); its pixel shader converts through
  the static combo `SRGB_OUTPUT_ADAPTER` (the engine's gamma-to-linear step for forced-sRGB framebuffers), which
  `sprite_dx12.cpp` sets whenever `$nosrgb` is on. Storing the gamma colour as linear lifted every sprite tail into a
  bright veil and washed out alpha-blended quads, which is why light glows had been suppressed; they are drawn
  again. The DX9 8-bit framebuffer blended these sprites in gamma space, which a linear target cannot reproduce, so
  additive glows can be slightly dimmer than `-dx9` over bright backgrounds. sRGB-writing sprites (`$nosrgb 0`,
  `SpriteCard`, additive `UnlitGeneric`) are unchanged.
- Content mounts must cover the map's VMT dependencies independently of shader publication. Half-Life 2: Update
  maps require `|appid_290930|hl2/hl2_pak.vpk`, not only the loose `hl2` folder. The episodic runtime mounts
  this archive after the SDK VPKs, retaining engine-matched shader priority. Missing Update-only `*_nocubbed`
  includes leave unresolved `patch` materials; registering a shader named `patch` is not a remedy.
  Verified on `d1_trainstation_01` after fast-forwarding the intro and returning to normal speed: stationary
  closed/open door captures show opaque metal and transparent windows, with failed includes and unknown
  `patch` errors reduced from 16 each to zero. Evidence: `_train_door_stationary_{before,after}_runtime.log`
  and `screenshots/train_door_stationary_{before,after}*.jpg`; both runs exited 0.

### CPU model facial flex

CPU-flex model shaders consume position/normal/tangent deltas through stream 2 and
`cFlexScale` (`VERTEX_SHADER_FLEXSCALE`, legacy VS register c3). The backend stages
`.x = 1` only while that draw has a mesh flex stream; `.y = 1` additionally requires
the real wrinkle channel. A 24-byte position/normal stream has `.y = 0`, preventing
the input assembler's default position W from becoming a false wrinkle weight.
The dedicated dynamic flex mesh retains the DX9 28-byte wrinkle layout.

This staging applies only to CPU-flex vertex consumers: native reflection identifies
`POSITION1`; translated shaders retain the original POSITION1 declaration independently
of the layout-pruned input signature. Missing-stream draws clear both switches, including
after a shader/memo transition. Unrelated shaders retain material-authored c3 (for example,
Compositor's c2/c3 UV matrix). CPU facial flex does not require static-prop baked lighting
or the hardware-morph accumulation path.

`shaderapidx12_smoke.exe -case flex -nativeroot <src/materialsystem/stdshaders_dx12>`
exercises rendered native `DX12VSEngine`/production `ApplyMorph` and translated legacy
shaders: position, normal, tangent and wrinkle channels, byte offsets, dynamic-buffer
overwrite preservation, flex/unflex/reenable, absent wrinkle and unrelated material c3.
`-case commands` also runs it. Supply the usual `-game`, `-sdkdir` and runtime DLL PATH;
`-dx12debug` checks the graphics debug layer.

After changing translation-result metadata, rebuild
`thirdparty/dx12_shaderconv/dx12_shaderconv_win64.vcxproj` before relinking
`materialsystem/shaderapidx12/shaderapidx12_win64.vcxproj` (Release, x64).
The renderer project links the prebuilt `dx12_shaderconv.lib`; a renderer-only build
with project references disabled does not rebuild that prerequisite. The flex-scale
fix changes neither published shader bytecode nor baked asset formats.

Live verification also exercised the actual `npc_barney` and `npc_kleiner` in
`d1_trainstation_01`: a temporary string-loaded choreographed scene held raw
`jaw_drop` and left/right `lid_closer` controllers with `scene_clientflex 0`.
Start/restart the hold only after the player reaches each actor's PVS; an
out-of-PVS actor does not receive the server flex update. The authored Kleiner
monitor camera position avoids the obstructed test view. Toggling `r_flex` 0/1
visibly restored the closed/open mouth and eyelid deformation, including reenabling
Kleiner's mouth. Captures: `_npc_flex_{barney,kleiner}_{on,off,on_repeat}.png`;
runtime evidence: `_npc_flex_surface_summary.json`. The owned game exited 0
and its saved configuration was restored. Particle/overlay changes mean these
screenshots are visual proof, not pixel-exact geometry measurements.

## Enhanced shadow receiver state and caster policy

Local realtime-shadow residency culls locals the main camera is not facing
first. The main view frustum is padded by 15 degrees of horizontal FOV per side so
a light about to enter view is promoted before it reaches the screen edge. A
light whose finite influence volume misses that frustum is never resident. Of
the rest, lights whose emitter lies inside the padded frustum outrank every
light behind the camera (most influences reach the view from anywhere, so the
emitter test is what separates them); within each tier the main camera's BSP
PVS and nearest emitter distance decide, with no radiance or contribution
scoring. `r_shadowmap_max_realtime_lights` defaults to four locals, excluding the
sun; zero removes the budget limit among eligible lights. Stable light IDs break
ties and 25% priority hysteresis prevents churn within a tier.
`r_shadowmap_realtime_fade_seconds` defaults to 0.5 seconds for the **complete**
handoff: all outgoing locals fade concurrently for 0.25 seconds, then incoming
locals fade in for 0.25 seconds. Turning or changing FOV never restarts a ramp,
but a turn that moves an emitter into or out of the padded frustum exchanges
lights through the same fade; first admission and positional jumps of at least
256 units select immediately.

`CShadowMapReceiverScope::Begin` refreshes the engine's cached receiver near/far
distances after nested shadow work through a balanced non-rendering
`Push3DView(setup, VIEW_NO_DRAW, NULL, NULL)` / `PopView(NULL)`. The engine's
ordinary pop restores matrices but leaves these distance caches unchanged;
`R_DrawSkyBox` sizes its geometry from the cached far distance. This fixes the
stationary white sky without changing shaders, disabling shadows or resetting
temporal history. An isolated enhanced `ep2_outland_06` run preserved normal
clouds while moving, after eight stationary seconds and while moving again,
with DX12 postprocessing both off and on, DLSS/frame generation retained and
actual shadow depth renders continuing.

Apply the viewmodel `DepthRange(0,0.1)` **after** receiver preparation, since
nested shadow views reset that range to `0..1`. The user verified the weapon
wall-clipping correction; additional viewmodel fixtures were stopped.

Client-local archived `r_shadowmap_force_physics_shadows` defaults to zero.
At one, native enhanced-map caster queries override authored `EF_NOSHADOW`
only for ordinary non-gib solid physics props. Hidden/nonsolid entities,
specialized subclasses, static-prop flags and material/translucency policy
remain excluded. Effects and save flags never change; live policy/eligibility
changes invalidate caster registration without requiring movement or respawn.
The computed ordinary-physics identity adds a `DT_PhysicsProp` bit, requiring
matching client/server DLLs. The user waived additional board-shadow fixtures;
no independent visible board-shadow proof is claimed.

Alpha-cutout casters: the engine renders prop/model shadow depth (and the flashlight depth texture) with its
`DepthWrite` override materials, whose cutout is the pixel shader's `clip` against `$alphatestreference`. The backend
drops the pixel stage of every depth-only or shadow-caster draw whose snapshot is not alpha tested, so `DepthWrite`
declares `EnableAlphaTest(true)` with `AlphaFunc(ALWAYS)` when it clips (the emulated fixed-function test then passes
everything and the shader's threshold stays the only one). Before this, every alpha-tested static prop and model
(chain-link fences, grates, foliage) was a solid shadow caster: `-dx12shaderlog` listed `depthwrite_vs51` but never
`depthwrite_ps51` on `d1_trainstation_02`. Brush `$alphatest` casters already carried the flag through their own wrappers.

Batched opaque casters: between `IShaderAPIDX12Lighting::BeginShadowCasterBatch` / `EndShadowCasterBatch` (queued
markers the client emits around the caster block of `CFeatureShadowDepthView::Draw` while `r_shadowmap_instancing`,
`FCVAR_ARCHIVE` default 1, is on) the backend does not record an opaque, rigid (`SKINNING`/`MORPHING` 0), fill-mode,
native `depthwrite_vs51` static-mesh draw; it keeps the draw's `cModel[0]` rows keyed by (mesh, index range, snapshot,
`COMPRESSED_VERTS`) and at the end marker (or when 4096 instances / 512 groups fill, or when a pass ends or nests)
uploads every group's rows once and re-enters its ordinary draw path per group with the native-only
`native_src/depthwrite_instanced_vs51.fxc` bound (same combo directives as `depthwrite_vs51`, only static 0 x dynamic
0..1 compiled) and an instance count. That shader reads the rows through `StructuredBuffer<float4> g_InstanceModelRows :
register(t0, space7)`, the vertex-stage root SRV `kRootInstanceTransforms` present on all three root signatures
(`DX12_INSTANCE_*` in `ishaderapidx12lighting.h`); the packer rejects any other space-7 binding and the backend validates
the shader by name (`ValidateInstancedCasterShaderDX12`), failing the recording with `SHADOWMAP_ERR_SHADER_UNAVAILABLE`
when the VCS is missing. Alpha-tested, skinned, flexed, tree-sway, dynamic-buffer or translated-fallback casters record
immediately as before; depth-only output is order independent. `-dx12stats` appends `rootSrvSets`, `shadowDraws`
(shadow-pass `DrawBuffers` entries excluding emission), `casterInstances` (captured draws) and `casterInstancedDraws`
(emitted instanced draws): with batching on `draws ≈ draws(off) − casterInstances + casterInstancedDraws`. Setting the
cvar to 0 stops emitting the markers (the unbatched path). Both paths write identical depth, so the toggle does not
invalidate cached charts; it applies to every depth scene rendered afterwards (cascades re-render as the view moves).

Sun sky clip (`r_shadowmap_sky_clip`, `FCVAR_ARCHIVE` default 1): the sky is the sun's emitter, as in the vrad_restir
bake, so nothing on the sun side of a sky face may cast. At admission the client reads the model-0 `SURF_SKY` faces
(plane normal as stored, `dface_t::side` does not flip it) and tags each with its sealed region (areas joined through
areaportals). Every sun chart (static sun and cascades; local charts pass no clip) hands `BeginShadowPass` a
`DX12ShadowSkyClip`: the entry faces (`dot( normal, sunTravel ) > 0`) of the receiver's region, already in the chart's
clip space. The backend rasterizes them with `shadow_sky_depth_vs51` (no pixel stage, `GREATER`, cleared to 0) into the
shared sky target, keeping per texel the entry sky nearest the ground. Caster draws in such a pass discard fragments on
the sun side of it (`native_src/shadow_sky_clip.hlsli`, bias 2 world units): opaque depth-only casters run
`shadow_sky_clip_ps51` instead of no pixel stage, and `depthwrite_ps51` / `dx12_detailshadowlit_depth_ps51` call the
same `ShadowSkyClip_Discard` (space 6 `t4` + `b2`). Brush `$alphatest` casters using their own pixel shader are not
clipped. A receiver on the sun side of a deeper entry sky in its own column (a roof above a window's sky brush) keeps
only the baked cap for casters above that sky. The extra pixel stage costs about 0.4 ms per frame while sun charts
re-render (`d1_trainstation_02`, RTX 4090); cached charts cost nothing.

Shadow depth targets are retained by physical owner rather than duplicated for every
pooled receiver packet. One shared static-sun work target (with a clean companion
only when oriented detail needs an overlay) and one cascade atlas pair per shadowed
receiver kind serve the main/viewmodel packet pools; unshadowed monitor, reflection,
and sky receivers allocate no sun targets. A nested receiver gets a work-only
copy-on-write target before writing a parent-sampled atlas, with queue ordering and
resource leases preserving the older packet exactly. Local pages retain their
4096-texel logical slot contract but allocate a power-of-two physical rectangle
covering assigned slots and grow by exact D32 depth copies; shader UV/texel
coordinates remain unchanged.

## Sky ambient match (`r_sky_ambientmatch`)

The `Sky` shaders (`sky_dx12.cpp` for LDR `Sky_DX9`, `sky_hdr_dx12.cpp` for `Sky_HDR_DX9`; compressed HDR multiplies `$color`
by 8 first) stage `$color` as pixel constant c0 and multiply the decoded sky by it in linear space, so a scalar on `$color`
scales the sky's luminance without changing its hue. No shader, wrapper or generated source changed. `vrad_restir` bakes the
factor into worldspawn (`_skyscale_ldr` / `_skyscale_hdr`; `utils/vrad_restir/README.md`, "Sky ambient match") and
`game/client/sky_ambientmatch_dx12.cpp` applies it. At `LevelInitPostEntity` it reads `skyname` and the key for the current
mode (`GetHDRType() != HDR_TYPE_NONE` selects `_skyscale_hdr`) from `engine->GetMapEntitiesString()`, holds the six
`skybox/<skyname>{rt,lf,bk,ft,up,dn}` materials and remembers their authored `$color`. Every frame it writes
`authored * factor` when `r_sky_ambientmatch` (`FCVAR_ARCHIVE`, default 1) is nonzero and the authored colour when it is 0,
touching a material only when its colour differs, so the cvar and a full material reload (`mat_reloadallmaterials`, which
re-reads the VMT) need no hook. `LevelShutdownPostEntity` restores the authored colours and drops the references. The feature
does nothing when the material shader DLL is not `stdshader_dx12` (`-dx9` is unchanged), when the map has no key (no
`light_environment`, an `UnlitGeneric` sky, ...), and after one Warning when a face material is missing or has no vector
`$color`. 3D skybox geometry is not a sky face and is unaffected. The renderer pins `mat_hdr_level` to 2, so
`_skyscale_ldr` applies on LDR-only maps.

Verification (isolated runs of `d1_trainstation_02` copies baked with `vrad_restir`; screenshots of the same sky view with the
cvar off/on/off, `mat_force_tonemap_scale 1`, camera `setpos -500 -3000 100`, `setang -80 0 0`): the `-restir_shadowmaps` copy
(HDR, `_skyscale_hdr 0.911622`) measures on/off 0.9094 in sRGB-decoded linear luminance with `mat_postfx_dx12 0`; a plain copy
with `_ambient` brightness 255 (LDR, `_skyscale_ldr 2.35721`, HDR lumps zeroed so the map runs in LDR) measures 2.3561, and
the cvar back at 0 returns pixel-identical frames. The legacy HDR post is not exactly linear (the same boosted copy in HDR,
factor 2.32464, measures 2.455), which is why the LDR run is the exact one. With `-dx9` the cvar changes nothing
(pixel-identical) and no sky is acquired. The enhanced copy loads with `Highres: state=2`. The runs' temporary maps, cfgs and
screenshots were deleted and the archived cvars they touched were restored in `config.cfg`.

## Explicit high-resolution BSP replacement

`tools/genhighres.py` catalogs actual RGB lightmap consumers: LightmappedGeneric/WorldVertexTransition,
WorldTwoTextureBlend, LightmappedReflective, the bumped decal pass, Water's base-texture pass,
ShatteredGlass, and PyroVision's world-lightmapped effects. `genmat.py` independently emits their
`*_highres_vs51`/`*_highres_ps51` twins alongside ordinary and old `*_shadowmap_*` shaders.
The decal self-illumination second pass samples only its base texture; cheap water/refraction-only passes
do not consume BSP irradiance. WorldVertexAlpha's DX9 draw is unreachable through its DX8 fallback;
DX8 fixed-function consumers are backend paths. The actual WorldVertexTransition editor assembly pass
uses authored `worldvertextransition_editor_highres_*` native replacements on enhanced maps, retaining its
texture transforms, two-material vertex-alpha blend and original sampled lightmap alpha.

Runtime `.hlight` ZIP readback can exceed 1 GiB while remaining below the file-size limit.
`CUtlBuffer::PutOverflow` must request the complete pending write (including representable trailing-NUL
space) in one `CUtlMemory::Grow` operation, not repeatedly call the default one-element increment.
Above 1 GiB the signed-overflow-safe allocator uses exact requested capacities, so the latter causes
byte-at-a-time full-buffer reallocations. The CPU-only `shaderapidx12_smoke.exe -case buffers`
regression exercises real >1-GiB growth, prefix/append/NUL preservation, ordinary growth policies,
seeking and fixed/growable/readonly external buffers. Rebuild static `tier1` and relink its consumers
after this implementation changes; shader bytecode and asset formats do not change.

The original base UV is carried before bump shifts, with no inverse-coordinate carrier input. Every highres vertex
shader also emits a `nointerpolation` copy of it (`shadowVertexLightmapUV` / `lightmapVertexUV`, the fixed-function
`tc12`): `HighresLightmap_Begin( baseUV, vertexUV )` looks the owning face up from that provoking-vertex UV, which is
always inside the face's allocation, and uses the interpolated `baseUV` only for the position inside the face (`q` is
saturated). Ownership is a property of the primitive, not of a fragment: the rasterizer covers pixel centers of
near-degenerate triangles (collinear T-junction fan triangles in BSP world meshes, surfaces seen exactly edge-on)
and extrapolates the UV far outside the triangle, which previously addressed unowned cells and produced the
"unowned native lightmap cell" rejections (`reason=owner ID`, `face=0`; also the earlier `ep2_outland_06` `coordinate bounds`
capture whose UV `1.00039` lay past the page edge).
It is not specific to the PBR shaders. Unknown owners are still rejected, now at the provoking vertex.
`native_src/highres_lightmaps.hlsli` translates the integer owner atlas into explicit face/style/plane tiles,
adds captured native dynamic planes, and preserves native sampled alpha. Material lighting retains its
existing bump/SSBump weights, two-material blend, tint and fog/output ordering; selected direct lighting
is gathered once and only selected sunlight is capped by the designated style-0/base alpha.
Receiver shader scheduling keeps each sun entry's orthographic chart in affine clip space, computed once before
PCF/PCSS tap loops. Four-tap sun/local preflight and PCF loops reuse one chart/compare body; selected-local PBR
lighting evaluates only the diffuse lobe required by the baked-direct domain. Continuous highres filter coordinates
do not carry `precise` (discrete owner/address decisions are unchanged), allowing normal multiply-add contraction.
The three bumped lightmap planes of a highres face share one bicubic footprint and one filter body
(`HighresLightmap_BumpedRGB`): the cubic B-spline taps depend only on the tile's texel extent, which the base tile
and the planes of a face have in common, so they are built once per pixel (both axes vectorised) and each plane
costs its tile record and four taps; the style slots are walked once for all planes. An earlier attempt that merely
serialized the three independent filters was slower in a stairwell view; this one measured 0.75-0.83 ms faster than
per-plane filters on a GTX 1050 (c1m1 roof and corridor, separate launches). The enhanced world shader went from
5011 to 4579 DXBC instructions (SHADOWQUALITY 0, range fog). The 1080p d1_trainstation_02 comparison retains the
same lightmap reconstruction, local shadows and sun penumbrae; these scheduling changes do not alter quality defaults.
Brush sun capping requires an explicit baked model pose equal to the draw transform.
The cap has two endpoints, blended by the summed weight `W` of valid CSM entries that were actually sampled
(`ShadowMap_SunResultCharted`'s `csmWeight`; the static whole-map entry does not count):
`min( runtime, lerp( bakedSunVisibility, bakedSunDilated, W ) )`. On highres receivers `bakedSunDilated` is
`HighresLightmap_SunDilated`: the max of four bilinear base-alpha taps at (+-1, +-1) texels, each clamped to the
tile's own texel centers, folded with the interpolated value. It is continuous (a max of bilinear functions), so the
bound never steps at texel boundaries; a 2x2-max of raw texels did, and showed as pixelated sun patches wherever the
cascade is lit slightly beyond the baked edge. Inside valid cascades, which already hold the static casters, the mask
therefore only vetoes about a texel beyond any lit texel, and PCSS penumbrae and thin runtime occluders are not
clipped to luxel shape. The PBR world shader skips the dilation taps where the bicubic base alpha is exactly zero: the
dilation reads the texels of that footprint, whose B-spline weights are all positive, so a zero result leaves nothing
to dilate (fully shadowed interiors pay no dilation). Legacy lightmap pages pass the scalar twice (exactly the scalar cap). Without a valid
cascade chart (disabled, deferred/cold, outside range) the interpolated scalar caps exactly as before. Every producer
sets both values through `ShadowMap_SetBakedSun`; a direct field write would leave `bakedSunDilated` at 1 and drop
the leak veto inside the cascades.
Sun PCSS (`SampleSunPCSS`) separates mixed-distance blockers. A single mean blocker depth lets a canopy hundreds of
units up dominate a post a few units above the ground; its wide kernel washed the post's contact shadow away
(d1_trainstation_02 bollards under the bare poplar). The blocker search also records the nearest and farthest
blocker. When their receiver distances differ by more than 6x (fully by 10x) and the classic result is a penumbra,
blockers split at the geometric-mean distance: the far layer reuses the classic taps (far blockers only, from the
same loads), the near layer is filtered again with the nearest blocker's kernel, and the visibilities multiply. Umbra,
full light and single-distance blockers return the classic result unchanged, so the second filter pass (the quality's
filter-tap count) runs only where both layers meet a penumbra.
Shadow filter dither (`native_src/shadow_dither.hlsli`, `r_shadowmap_dither`, archived, default 1): `ShadowMap_BeginReceiver`
rotates the sun PCF/PCSS blocker and filter patterns, the local 4-tap PCF and the projected-light 4-tap PCF per pixel by
interleaved gradient noise, turning tap-pattern staircases into noise. The view packet's `cViewForward.w` carries the
control: 0 off (fixed patterns, the smoke fixtures), 1 + n with n = `framecount & 63` in the main/viewmodel views under a
temporal upscaler and 0 otherwise (the GTAO/volumetric convention). Rotated 4-tap PCF has radius sqrt(0.5) texels, so its
plane preflight checks a +-0.75 square instead of +-0.5. Measured at the two d1_trainstation_02 spots with PCSS:
+0.06 / +0.12 ms GPU.
`volumetric_ps51` runtime contract (screen-space volumetric march): the low-quality profile (`r_volumetric_quality 0`,
8 light-segment samples) runs the march at quarter resolution (one texel per 4x4 full-resolution footprint), while
balanced/high profiles retain the half-resolution march. Every provider receives the same rotating per-step IGN sequence:
`cVolumeControl.w` is `framecount & 63`, and each step offsets the sequence independently. The temporal pass below
integrates this dither before compositing, so r0, DLAA, FSR and native SMAA converge to the same shaft instead of
depending on an AA provider to hide march slices.
`volumetric_temporal_ps51` resolves the current reduced-resolution RGB scatter and representative depth against ping-pong
RGBA16F history. It reprojects from the footprint centre using the previous camera transform, prefers the closest scene
depth/motion sample in the footprint at silhouettes, rejects history when depth differs beyond the upsample tolerance or
the camera/resolution changes, and blends up to 0.9 history (reduced on motion). When no valid motion texture is available,
the camera-only reprojection is used. The two quarter-resolution history targets are about 2 MiB total at 1920x1080
(about 8 MiB for the half-resolution profile), reported under the `volumetric` dx12_memreport category.
The depth-aware 4x4 composite remains unchanged and preserves the same depth-edge rejection, medium/strength/anisotropy/
max-distance controls, opted-in local/projected lights, sun cascade/static-chart selection and four-tap sun PCF. The
quarter path reconstructs its representative camera-forward depth from the selected hardware-depth endpoint before ray
marching, so wall blocking is preserved; its expected visual difference is modest extra softness. The CPU `SunProjection`
is orthographic (w = 1), so the five named scalar ray start/step transforms and atlas dimensions are hoisted out of the
march loop. Projected lights similarly transform the ray start/step once and reuse the interpolated homogeneous coordinates
for both frustum rejection and `DX12_ProjectedSampleClip`; cookie, attenuation and shadow filtering are unchanged.
Sun PCSS sample budget: the PBR pixel shaders carry a `SHADOWQUALITY` dynamic combo (0..3) set from
`r_shadowmap_filter_quality` (stdshader_dx12, archived, default 1) and selecting the Vogel tables of
`native_src/shadow_pcss_disks.hlsli`: Low 8 blocker / 8 filter taps, Medium 8/16, High 16/32 (the original budget, and what
every shader without the combo compiles), Extra 32/64. `pbr_model_ps51` skips the combo outside its ENHANCED receiver
variants. Low and Medium also skip the screen-space contact ray toward the sun (`DX12_SUN_CONTACT_SHADOWS`; local and
projected contact rays keep running), which cost more than their whole PCSS kernel at the bollards reference spot. The
graphics options expose it as the Shadows row: Off (`r_shadowmap_enable 0`), Low, Medium, High, Extra.
Measured at the two d1_trainstation_02 spots (PCSS, dither, DLSS) before the Low/Medium contact skip: Low 2.89 / 4.11,
Medium 2.84 / 4.03, High 3.11 / 4.35, Extra 3.57 / 5.12, Off 2.30 / 2.89 ms GPU. One bollards run after the skip (same
machine state, Off 3.31 vs 3.29 ms) measured Low 4.41 and Medium 4.36 ms against Medium 4.55 ms before (about -0.2 ms).
An unknown owner or malformed shader-side address sets `HlightFailure` (`u0 space3`); it is not a
white/unmasked fallback.
A known neutral `route.enabled=0` preserves native RGB/alpha, native normalization and the selected-direct
gather; an invalid owner with `route.enabled=1` contributes neither baked RGB nor selected direct while
the real GPU failure is reported. Neutral metadata-only maps are not mistaken for malformed owners.

The failure UAV now records nine uint32 words:
`{flag, reason, page+1, cellX, cellY, face+1, UVbitsX, UVbitsY, detail}`.
An atomic claim selects one complete failing invocation; other pixels cannot mix their payload into it.
Reasons distinguish coordinate bounds, owner ID, tile index, page group and lightstyle failures.
The renderer initializes/copies/maps all 36 bytes, using four-byte upload elements.
The renderer prints the decoded rejection as a Warning and then executes `DebuggerBreak()` unconditionally (debugger or
not), before the fatal error and before unmapping its readback: without a debugger the unhandled breakpoint reaches the
process crash handler, which writes the minidump. The breaking frame (`BreakOnHighresFailure`) holds a `FailureDump`
local with the nine-word record, UV, fence, the previous clean readback fence, map generation, the message, the distinct
vertex/pixel shader pairs and the newest 16 draws (shader pair, mesh token, first index/count) that the failing page
received between the previous clean readback and the failing one (recorded per draw in a 4096-entry ring, no
allocation). The failure UAV names only a page and a command-list window, so these are the candidates, not an exact draw.
Continuing from the breakpoint executes the existing fail-closed rejection.
The RTX 4090 `highresgpu` fixture verifies concurrent rejection records with GPU validation;
its shadow resources use the production 4096-square physical atlas, not a normalized one-texel substitute.

Receiver-plane shadow filtering compares each of the four physical texel centers against its own
plane depth, then bilinearly blends visibility. A single reference passed to hardware bilinear
comparison can self-shadow a diagonal receiver despite having no blocker.
Sun charts use an orthographic depth gradient; local charts use the perspective plane gradient,
including remapped cube-face bases. Degenerate-plane fallback and caster bias remain unchanged.
The production `shadowmaps` smoke on RTX 4090 passed PCF/PCSS diagonal-plane phase coverage:
unblocked visibility was exactly 1 and real-blocker visibility exactly 0, with no debug-layer errors.

The packer publishes `<logical>.hlight` beside each participating VCS: four little-endian uint32 words
`{0x544c484e, 1, lightmapSamplerMask, highresAbi}`. Ordinary/old variants carry original sampler roles;
highres vertex variants carry mask zero and ABI one. Roles include reflective/water sampler 3 and decal
samplers 1/2/3. The backend selects matching highres variants from this metadata, not material names.
The packer also emits `generated/inc/highres_lightmaps_hlsl.inc` and `shadowmap_lighting_hlsl.inc` for
backend-owned fixed-function compilation without an include handler.
Lighting interface `_005` copies explicit native generation/route and all 64 view-consistent lightstyles;
the separate highres draw cbuffer is 320 bytes (`route`, three model rows, sixteen packed style rows).
After generator changes run `gencommon.py`, `genmat.py`, rebuild/publish with the updated native packer,
then rebuild both backend and material DLL against the regenerated includes.

Large SM5.1 programs can exceed Source's nominal 128 KiB compiler block-batching target.
The shared runtime/publisher VCS reader admits raw, bzip2 and Source-LZMA decoded blocks
up to a separate hard 16 MiB limit, preserving complete span/header/token validation.
Bzip2 storage grows only when required; LZMA's declared size is bounded before allocation.
The `vcs` smoke covers oversized raw/bzip2 DXBC and oversized LZMA-header rejection.

Hybrid local visibility uses lighting shader ABI 6 (shader API interface `_007`) and retains the appended
16-byte GPU light row (`realtimeWeight`, `visibilityFlags`, canonical manifest `bakedLightIndex`, zero `reserved0`).
`gencommon.py` owns the engine cbuffer/record source as well as the translated common headers.
The native world owner join exposes the active mode's zero-based face ordinal and endpoint-normalized `q`;
only valid lit owners in their exact baked model pose are eligible. Static props additionally require an
exact prop ordinal/checksum/pose and hardware mesh identity join at the draw boundary. Moved brushes,
dynamic models, detail and unmatched prop draws have no baked domain and use baked visibility 1.
Native-only/unlit passes retain their existing no-selected-direct policy.

Read-only map visibility SRVs are model-neutral space2 bindings: `t1030` face
`uint4 {firstEntry, entryCount, highWidth, highHeight}`, `t1031` sorted disk-form entry
`uint4 {selectedLightIndex, encoding, payloadByteOffset, sampleCount}`, and `t1032`
R8 `ByteAddressBuffer` payload. The shader lazily loads the face range and computes endpoint-clamped
bilinear taps only after the first bounded-skip survivor needs baked visibility. A persistent ascending
merge cursor visits each encountered entry at most once for all queried canonical manifest indices.
The highres packet validator requires canonical light order and ascending CSR runs; `BuildLocal` and
`BuildTiles` already preserve both. Uniform encodings decode directly without reading payload bytes.
Receivers without baked direct keep the existing full CSR hybrid evaluator: weight 1 skips baked
lookup, weight 0 never constructs or samples a chart, and diffuse/specular share blended visibility.
Editor lights are unbaked dynamic entries in the same per-view list (`realtimeWeight` 1, no
`DX12_SHADOW_VISIBILITY_BAKED_AVAILABLE`, `DX12_SHADOW_VISIBILITY_UNSHADOWED` when the light has no shadow chart).
Both gathers (`PBR_GatherDirect`, `ShadowMap_GatherDirect`) treat a light as a baked delta only when `BAKED_AVAILABLE`
is set, and sample the realtime PCSS chart only when the weight is positive and `UNSHADOWED` is clear. An editor light
is therefore a full term on every receiver, PBR and legacy (`bakedVisibility` 1, `realtimeVisibility` the chart or 1).
The baked-only specular tail still walks receiver entries only.

Static-prop draws add `b1 space2 DX12StaticPropDrawConstants`: `uint4 cPropDraw`
`{firstEntry, entryCount, primitiveBase, primitiveCount}` followed by three `float4 cPropModelToWorld`
rows, `uint4 cPropDirect {RGBByteOffset, angularPlaneStrideBytes, unbakedIDByteOffset, unbakedIDCount}`
and `float4 cPropStyles` (96 bytes total). Unused style values are zero; a missing direct offset is
`0xFFFFFFFF`. A zero primitive count explicitly disables this receiver domain. Immutable
`t1033 g_ShadowVisibilityPropMeshes` holds `uint4 {firstEntry, entryCount, vertexCount, flags}`;
flag bit 0 identifies a mesh with baked direct planes.
per-draw `t1034 g_ShadowPropTriangles` holds 64-byte records: `uint4 vertexIndices`
(three baked vertex IDs plus absolute mesh-directory index), then three actual local `float4 positions`.
All ten lit model feature PS families carry raster `uint SV_PrimitiveID`: basic/bumped VertexLitGeneric,
Phong skin, eyes, eye-refract, plain/bumped teeth, treeleaf, cable and vortwarp. The system semantic is
PS-only and does not alter paired VS interpolators or combo ranges.

`ShadowMap_SetBakedProp` carries the primitive identity without touching SRVs.
`ShadowMap_BeginBakedLookup` lazily validates the directory range/vertex bounds, transforms the actual
draw triangle by the model rows and computes barycentrics once per pixel without advancing the entry
cursor. Direct RGB and R8 lookup share that reconstruction; each dense visibility entry uses exactly
three scalar R8 reads, while uniform entries decode directly. Degenerate/disabled primitives return
visibility 1 and do not enter baked-direct evaluation.

`.hlight` v4 prop direct blocks carry RGBA16F linear irradiance already divided by 255, ordered
style → angular plane (0 Lambert, 1 half-Lambert) → vertex, followed by sorted style-overflow light IDs.
For valid original-pose prop draws in angular modes 0/1, the shader uses `Load2`/`f16tof32` to interpolate
three vertex RGB samples per active style and add frozen view style values before material albedo.
It then visits only the resident tail merged with that mesh's sparse unbaked list: resident baked
diffuse adds exact runtime radiance/angular × `(Vrt - Vbaked) * weight`; specular uses `Vrt * weight`.
Overflow entries retain the full hybrid term and are merged once when also resident. Unsupported
angular modes (including bumped-basis mode 2), dynamic/no-direct props and unknown draws retain the
full runtime loop with the existing baked/realtime R8 crossfade. World baked-direct behavior is unchanged.
Only read-only resources are added: alpha/discard, coverage, depth output and early-depth policy are unchanged.
The publisher and runtime validate the prop cbuffer members, 64-byte structured triangle layout, complete
prop resource group and primitive system input; stale ABI-5 lit model programs must be republished.
For `.hlight` v4 world owners with `kFaceHasBakedLocalDirect` (bit 16) and the exact baked pose,
RGB lightmap planes contain styled local direct diffuse for lights whose styles fit the face palette.
These pixels read the resident GPU-index tail of `t1028` (`cSunIdentity.zw` is offset/count), not the
tile CSR, and merge sparse per-face style-overflow exceptions when present. The resident tail contains
every positive-weight record in ascending GPU-index order; its bounds, exact membership and CSR
separation are validated before receiver binding. No resource, record, cbuffer or interface ABI changes.
Resident diffuse adds `radiance * angular * (Vrt - Vbaked) * weight`; specular adds
`radiance * specularAngular * Vrt * weight`. Baked visibility is required even at weight 1 to subtract
the pre-existing baked diffuse. The bounded skip scales its unshadowed diffuse/specular bound by
weight; skipped diffuse delta is zero and skipped specular uses the bounded `Vrt = 1` stand-in.
Style-overflow lights absent from that face's baked palette retain the full hybrid diffuse/specular
term `radiance * angular * lerp(Vbaked, Vrt, weight)`, including nonresident lights at weight 0.
The sparse disk face ranges and canonical light indices are validated with the v3 asset. GPU upload
appends the canonical uint32 lists after the aligned R8 payload in the existing `t1032` raw buffer,
without copying the CPU visibility planes. Owner metadata packs count into `dimensionsFlags.z`
bits 16..31 and raw uint offset into `dimensionsFlags.w` bits 1..31 (bit 0 remains baked-pose-known).
Empty lists need no additional directory/payload load or canonical-to-GPU lookup. Nonempty lists
resolve their fallback IDs to view lights and merge them with the resident tail, evaluating overlap once.
The PBR kernel resolves an ID with one load of the view's canonical light map (`PBR_ViewLightIndex`): interface
`ShaderAPIDX12Lighting_014` publishes, after the resident tail of `t1028`, `canonicalMapCount` entries holding
view light index + 1 per manifest light ordinal (0 = not selected by this view; the backend validates that it
holds exactly the view's `BAKED_AVAILABLE` records). Style-overflow lists are common in c1m1 (flickering
fire-lit rooms exceed the four-style palette), where the previous per-ID binary search over the 608-byte view
light records was a measurable part of the world pass; legacy receivers keep that search
(`ShadowMap_UnbakedViewIndex`). Delta-only lights retain the weight-scaled bound; unbaked
lights use the full-term bound. Debug blocker/radius modes bypass both skips and observe the union.
Old asset layouts are rejected and require a rebake. Sun and non-baked receiver policy are unchanged.
Early-depth twins add no new discard, depth or coverage output and preserve the late highres failure report.

### Forced early-depth receiver twins

Highres receiver PS variants additionally have `*_highres_earlydepth_ps51` twins. They preserve all
combo directives/fold slots, material blocks, lightmap sampler roles and color/alpha calculations.
Every conditional `main` is annotated `[earlydepthstencil]`; `DX12_EARLY_DEPTH` preprocesses the
shared `DX12AlphaTest` kill away. Select these twins only with runtime alpha test disabled and
effective alpha-to-coverage disabled. Fixed-function highres PS compilation must use the same
compile-time specialization and include it in the shader cache key; a runtime alpha-test branch
or a PSO-only change is not sufficient.

The generated families are `lightmappedgeneric`, `lightmappedgeneric_decal`, `lightmappedreflective`,
`worldtwotextureblend`, `water` and `shatteredglass`. The hand-authored
`worldvertextransition_editor_highres_earlydepth_ps51.fxc` includes the ordinary editor receiver
under the same specialization, retaining its original combo ABI.

`genhighres.py` audits the full include closure, retaining all combo-dependent branches and
excluding any shader with active `clip`, `discard`, `texkill`, depth-output or coverage semantics.
Current receiver families have no such exclusions: the flashlight helper's four legacy kills are
inside `_X360`-only branches, absent on PC; raster alpha testing is removed only in the safe twin.
Depth written into destination **alpha** remains unchanged and is not `SV_Depth`.
Future unsafe receivers keep their original PS and receive a `# earlydepth-excluded` manifest
reason, not a safe-twin declaration.

Manifest `# earlydepth <base> <twin>` declarations produce an optional `<base>.earlydepth`
sidecar containing two little-endian uint32 words `{0x59445245, 1}`. The packer verifies both PS
records have matching combo indices/folds, sampler metadata and reflected material blocks before
publication. `ShaderVcsFile::EarlyDepthTwin()` reads this admission bit; absent metadata means
false, while malformed metadata or a missing declared native twin fails the load. Existing
`.hlight` metadata is unchanged. Ordinary shaders and twins with alpha testing/A2C retain their
original execution. Visible malformed/unowned receiver cells still report `HlightFailure`;
depth/stencil-hidden failure writes intentionally disappear in the early-depth specialization.


### Main-view opaque depth prepass

`r_depth_prepass` replays the already-built mono main-view world/renderable lists before opaque color.
World submission uses ordinary `DrawWorldLists` with the current opaque water-side sort groups,
but no skybox or water surface. Models and static props use `DEPTH_MODE_NORMAL`, not the studio
shadow-texture path: color and prepass keep the same LOD, skinning, flex, vertex shader, viewport
epilogue/jitter, culling and raster bias. The color pass retains its ordinary nearer-or-equal depth
comparison; the prepass adds no compensating depth bias.

Ordered `IShaderAPIDX12ScreenSpace` markers enable a backend-only draw mode, independent of SSR
and contact-shadow enable. It admits only opaque depth-tested depth writers, drops decals/overlays
and non-depth-writing ancillary effects, masks color/G-buffer/stencil writes, and removes the PS
only for fixed-coverage draws whose native DXBC declares forced early depth. Opaque shaders with
unaudited discard/texkill or depth/coverage output retain their original PS. Alpha testing, A2C
and clipping remain authoritative. PBR cutouts
use `pbr_world_depthprepass_ps51` / `pbr_model_depthprepass_ps51`: wrappers of the original source
with the same combos and material block, returning immediately after the unchanged alpha test.
Their RTV0 alpha is preserved for A2C; no receiver lightmap/light/IBL work is evaluated. The
ordinary color VS is resolved before selecting the coverage PS, so reduced PS metadata cannot
change the vertex route. Other cutout materials keep their original PS.

Default selection is performance-gated: compare both total GPU time and lit PS invocations with
`r_depth_prepass 0` / `1` in the same run; saving opaque color time alone does not justify enabling
the extra geometry pass.

### Baking an enhanced map

After VBSP/VVIS, run from `src` (PowerShell), using a game directory that resolves the map's assets:

```powershell
& ..\game\bin\x64\vrad_restir.exe `
  -game ..\game\mod_episodic `
  -restir_shadowmaps -restir_hlight_density 4 `
  -final -restir_iterations 128 -restir_seed 1 -restir_denoiser none `
  "F:\path\to\map.bsp"
```

The versioned `.hlight` asset is embedded in the BSP pak; deploy the BSP, not a separately named loose file.
The native BSP lightmap grid stays unchanged (`-restir_lightmapscale 1`, the default).
Density 1 uses native-resolution sampling; density 2 and 4 independently bake approximately 4 and 16 times
as many surface sample locations, respectively. Density changes neither iteration count nor bounce count.
`-restir_shadowmaps` currently forces paired LDR/HDR baking and enables static-prop lighting/texture shadows,
even with `-hdr`. Runtime HDR-first selection does not yet eliminate that second bake.

Without a preset, quality is 128 iterations, 8 local-light candidates, 4 maximum bounces and balanced OIDN.
Bare `-final` selects 512 iterations, 16 candidates, 6 bounces and high-quality OIDN.
The command above explicitly overrides final iterations to 128 and disables denoising; explicit options
win regardless of argument order. `-fast` selects 32 iterations, 4 candidates, 2 bounces and fast OIDN.

The renderer reports Source material tier **110**, distinct from its D3D12 API and minimum device feature
level 11_0. It pins `mat_dxlevel=110` and `mat_hdr_level=2` (integer HDR; Source's float HDR mode 3 is not
implemented, and the engine persists `mat_hdr_level` in the registry, so any other value is reset on load and on
every change): HDR-capable maps use HDR lighting, while genuine LDR-only maps retain the engine's LDR fallback.
HDR monitor output is a separate setting.
Legacy enhanced manifest v3 maps require a rebake; the abandoned inverse-addressing path is not a fallback.


## Native-only shaders

Native-only is reserved for DX12 shaders with no meaningful DX9 implementation or combo-ABI reference. Register one
with `native_only(...)` in `tools/pairs.py`; `genmat.py` emits `<source> <vs|ps|cs> <logical> native -` and the source
must live in `native_src/`. The packer still enforces DXBC stage/VCS version, combo-count sanity, cbuffer reflection,
space-1 declarations and native cbuffer registry generation, but performs no legacy compile or parity comparison.
The runtime has no legacy fallback for these logicals, so the published native VCS is required.

## Compute shaders

Compute manifests use the same native-only form with a `cs` stage:

```text
gtao_main_cs51.fxc cs gtao_main_cs51 native -
```

`process_shaders.ps1 -Native` compiles this with `ShaderCompile2 -ver 51`, which derives the `cs_5_1` profile,
emits the VCS v6 combo table and a normal `<logical>_Static_Index` / `<logical>_Dynamic_Index` include, and passes
both artifacts to `nativeshaderpack_dx12`. The packer validates a compute DXBC program, requires `b0 space1` for
the constants cbuffer (at most 512 bytes, `SHADERAPIDX12_COMPUTE_MAX_CONSTANTS`) and `t*`, `u*`, `s*` resources in space 0, then publishes
`<game>/shaders/csh/<logical>.vcs` and records it in `native_dx12_published.txt`.

Compute includes intentionally contain no graphics native-cbuffer block writer. Material C++ passes the reflected
`b0` bytes directly through `IShaderAPIDX12Compute::Dispatch`, binds SRV/UAV resources to the generic root signature,
and calls `Draw( false )` for material bookkeeping. The runtime loader opens `VcsStage::Compute`, which reads from
`shaders/csh/` and rejects non-compute DXBC.

## PBR shader set (`mat_pbr_override`)

Plan and design record: `src/DX12_PBR_SHADER_SET_PLAN.md` (probe phase: `src/AMBIENT_PROBE_GRID_PLAN.md`).

Material shaders (`cpp/pbr_dx12.cpp`, the `PBR_*` adapters at the end of `cpp/lightmappedgeneric_dx12.cpp`,
`cpp/vertexlitgeneric_dx12.cpp` and `cpp/worldvertextransition.cpp`, shared code `cpp/pbr_helper.*`):

| Shader | Inputs |
|---|---|
| `PBR_Metalness` | `$basetexture`, `$bumpmap`/`$normaltexture`, `$mraotexture` (R metalness, G roughness, B AO; `$metalness`/`$roughness`/`$ambientocclusion` multiply it, or are absolute without it), `$emissiontexture`, `$envmap` (write `"$envmap" "env_cubemap"` in the VMT so VBSP patches it), `$envmapmask`, `$detail` |
| `PBR_Specular` | same, F0 from `$speculartexture` (sRGB) or `$specularcolor` instead of metalness |
| `PBR_LightmappedGeneric`, `PBR_VertexLitGeneric`, `PBR_WorldVertexTransition`, `PBR_Skin` (fallback to VertexLitGeneric) | the original shader's parameters, always drawn with PBR |

All of them, and the original wrappers, also accept `$subsurface`/`$subsurfacetint`, `$backlight`/`$backlighttint`,
`$thickness`/`$thicknesstexture`, `$anisotropy`/`$anisotropyrotation` (degrees) and the VBSP parallax keys
`$envmapparallaxobb1..3`/`$envmaporigin`. Studio models with `PBR_Metalness`/`PBR_Specular` need the usual `$model 1`.

`mat_pbr_override 1` (`FCVAR_ARCHIVE`, default 1, in this DLL) routes LightmappedGeneric, VertexLitGeneric and
WorldVertexTransition through the PBR path at runtime when `PBR_LegacySupported` accepts the material. The backend's
committed state starts at the default, so materials load with it from the first frame; a changed value is a request
committed by the client at `FRAME_START` inside a material transaction, followed by a preserving refresh of loaded
materials; draws read only the committed value.

The L4D2 compatibility adapter preserves decals, `$vertexcolor`, `$ssbump` and `$ssbumpmathfix`, blend tint,
Phong tint/boost/Fresnel ranges, self-illumination masks, flashlight-no-Lambert, tree sway, linear-write and
diffuse-modulation controls, `$diffuseexp`, and the authored detail blend modes (world 0..12, model 0..9).
The original shader keeps ownership when the adapter cannot reproduce a feature: spherical envmaps, lightwarp or
Phong warp, model `$lightmap`, rim lighting, distance alpha, seamless model mapping, `$selfillumfresnel`,
`$shinyblood`, world seamless mapping, outline/soft edges, vertex fog, or an out-of-range detail mode.

Conversion of legacy inputs: dielectric F0 0.04; roughness from explicit PBR inputs, else the Phong exponent
(`exp = 1 + 149 * R` in `l4d2_phong_ps20b.fxc` / `skin_ps20b.fxc`, unless a nonzero `$phongexponent` overrides it,
converted as `(2/(exp+2))^0.25`), else the envmap mask as gloss (roughness = 1 - mask, the mask no longer scales
the reflection; `$envmaptint` does), else 0.6.
With an exponent texture and `$phongalbedotint`, G tints the Phong specular colour toward the linear albedo
(`l4d2_phong_ps20b.fxc:121`, `skin_ps20b.fxc:271-276`); the legacy diffuse albedo is retained, not converted to metal.
R remains the exponent channel, not a color channel; A remains the legacy rim mask only when rim lighting is enabled,
and rim-lit materials stay on the legacy shader. `$envmapmask`, `$basealphaenvmapmask`, and `$normalmapalphaenvmapmask`
continue to select the legacy environment mask in the opt-in adapter. For legacy L4D2 Phong materials, `$envmap`
uses the authored mask and `$envmapfresnel`/Phong Fresnel ranges as in `l4d2_phong_ps20b.fxc`; it is not attenuated
by the dielectric PBR EnvBRDF. `$phongboost` is folded into bounded F0 (rather than multiplying a normalized GGX lobe),
while diffuse albedo remains energy-conserving. There is no `$phongalbedoboost` parameter in the retail/source shader
vocabulary. Detail blend factor/tint, `$vertexcolor` (world), `$nodiffusebumplighting`, `$alpha2`, `$envmapmasktransform`,
`$bumptransform2`/`$bumpmask` follow the legacy LightmappedGeneric math.

Lighting (all PBR materials alike): GGX with height-correlated Smith visibility, pre-multiplied by pi so units match the
legacy `albedo * NdotL * C`; Lambert diffuse where the term must match stored baked data (lightmaps, ambient cube,
probes, the signed baked deltas), Burley for realtime-only lights. Direct specular comes from every light: realtime
lights use `lerp(Vbaked, Vrt, weight)` visibility, baked-only lights their stored baked visibility. IBL samples the
cubemap mip `roughness * (mips-1)` (the DX12 renderer adds `-forceallmips` so mip tails exist) with Karis'
`EnvBRDFApprox`, optionally parallax-corrected by the VBSP box. Lightmaps, the ambient cube and the dense probes are
diffuse-only carriers multiplied by the diffuse colour once. Flashlight and `env_projectedtexture` (at most 8 per main
view, nearest first) are cookie spotlights inside the same pass; the engine's additive flashlight pass draws nothing
for PBR materials.

High-resolution receiver residency keeps the baked pixels lossless while trimming unused allocation edges. HDR pages are
uploaded into cropped power-of-two array classes (the 2048/4096/8192/16384 bindings remain ABI names; their dimensions
come from the selected class). Native R32 owner pages remain full-size because owner lookup uses full native UV dimensions;
only the HDR payload arrays are cropped. Native RGBA32F dynamic companions are lazy: a shared 1x1 zero page is bound until
a captured nonzero dynamic plane is published, so maps with no executed dynamic contribution do not reserve companion pages.

The GPU face directory is 132 bytes (`owner`, packed style IDs, four tile indices, and the three baked model rows), down
from the former 160-byte record. Tile records are packed to three uints (12 bytes), down from 32 bytes; page kind/slice,
class exponents, origin, and extent are losslessly unpacked in the shader. On `d1_trainstation_02`, this saves
`6605*28 + 10247*20 = 389880` bytes of immutable metadata before resource alignment. The selected HLight mode has
four 2048-square 128-MiB RGBA16F payloads; its fourth page uses only a 2048x1024 class, reducing resident HDR payload
by 16 MiB. Its five native RGBA32F companions (8 MiB each in the untrimmed path) are omitted when no nonzero dynamic
capture is present. No format precision or receiver filtering coordinates change.

Enhanced receiver traffic: the 608-byte runtime light records retain full float precision. Radius/fade rejection
reads only the light ID, origin/radius and fade bounds (28 bytes), deferring the remaining header until the light
passes; baked-only specular similarly checks weight/origin before attenuation and cone data. A local chart reuses
its home-face matrix and rectangle when the unbiased receiver belongs to that face, rather than fetching that
same matrix again. Projected lights reject receiver classes using just their flags.

The immutable visibility upload keeps the disk data unchanged but uses the GPU-only entry `.w` lane for a live
bitmask at the first entry of each receiver-local 32-entry chunk (faces and prop meshes separately). The mask
contains exactly the entries whose stored visibility is nonzero, including dense payloads; partial chunks have
no out-of-range bits. PBR baked-only enumeration reads one 4-byte mask instead of 32 scalar visibility loads
(128 bytes spread over a 512-byte record span); empty receiver lists read no mask. Buffer strides and allocation
sizes are unchanged. Unknown/neutral highres world owners skip the selected-direct gather outside debug views.

Lightmap filtering: the PBR world highres twins (`pbr_world_highres_ps51`, `_earlydepth_ps51`) define
`HIGHRES_LIGHTMAP_BICUBIC`, so every `.hlight` tile read in `HighresLightmap_Tile` is a cubic B-spline built from four
bilinear taps, each clamped to the tile's texel-centre rectangle (no bleeding from neighbouring tiles). Captured native
dynamic additions (`HlightDynamic`) stay bilinear, and legacy highres shaders are unchanged. The native lightmap path
(ordinary maps, native-only faces) stays bilinear: native face allocations are `(extents+1)²` with no gutter
(`engine/gl_matsysiface.cpp`), so a ±1.5-texel footprint would read neighbouring faces. Cost per pixel: 4 taps for a flat
single-style face, 4 base + 12 plane taps (+3 dynamic) for a bumped one, +4 per plane for each extra style; the
footprint arithmetic is paid once per pixel (again only for a tile whose extent differs from the base tile's).

Native logicals (`tools/pairs.py` slice `pbr`, `manifests/pbr.txt`): `pbr_world_vs51` (4), `pbr_world_ps51` (12), their
`pbr_world_highres_vs51`/`_ps51`/`_earlydepth_ps51` twins selected by the backend on enhanced maps (4/12/12),
`pbr_model_vs51` (48), `pbr_model_ps51` (24; `ENHANCED` adds the receiver lighting ABI and dense probes),
`pbr_gbuffer_debug_cs51` (2). Register space 5 (`t0` 128-byte `PBRSpotGpu` records, `t1..t12` cookies, `t13..t24` depth,
`s0`/`s1`) is backend-owned: eight ordinary projected lights plus four reserved survivor flashlights. Array capacities
come from `public/shaderapi/projected_light_limits.h`. Space 4 carries the probe grid. All PBR includes are new files, so legacy payloads are
unchanged. `shaderapidx12_smoke -case pbrgpu` checks energy, workflow equivalence, the isotropic/Lambert limits and
parallax; `-case probegpu` the probe decode.

Enhanced PBR models use the archived `r_model_local_lights` budget (default 4, range 1–4; 0 selects
the original full per-pixel list). `IShaderAPIDX12Lighting::ModelLocalLighting` runs on the recording
owner using `CShaderAPIDX12::m_LightingOrigin` and the current retained view packet, with fixed-size
stack storage and no per-draw allocation. It ranks lights by linear irradiance after the authored
radius, distance falloff, cap, fade and spot cone; positive realtime weights take precedence.
Material registers c40–c46 carry four packet indices and six ambient-cube RGB rows. The selected
lights still use the normal BRDF, baked visibility and realtime shadows. The sun, projected lights
and world lightmapped receivers are unchanged. Other direct lights are projected onto the six cube
axes at the draw origin (unshadowed retail-style approximation), then squared-normal weights add
that cube to dynamic models' probe/engine ambient. Exact static-prop receivers retain their baked
direct carrier instead, avoiding a second diffuse contribution. Dense probes themselves contain
leaf ambient, not the omitted ordinary point/spot direct light.

The highres PBR world route avoids native-lightmap samples whose RGB is immediately replaced
by `.hlight` RGB; native-only owners keep the same gradients and native scale. Fully sunlit
receivers (`sun == 1`) skip dilation samples because the saturated dilation cannot raise that
bound. World baked-visibility interpolation is cached once per receiver, and an exactly-zero
dense visibility sample rejects baked-only specular before attenuation/GGX evaluation. A bumped
lightmap plane whose weight is exactly zero is not fetched (zero times finite RGB is zero).
These do not change lighting quality. In `PBR_GatherDirect`, standard-light radiance is evaluated
from individual `g_ShadowLights` member reads (`PBR_RadianceInRangeFields`) instead of
materialising the 608-byte light per pixel; the full light is loaded only inside the
realtime-shadow branch that reads its matrices/rects. Same fields, same math, same order.
Static-sun copy-on-write also omits preservation only when a pending clean rebuild overwrites
the entire replacement target before receiver use; cascade preservation remains unchanged.

`r_world_baked_specular` (archived, default 0) reaches world draws as c40.y. At 0
`PBR_GatherDirect` skips the baked-only specular loop (and its entry-list directory and live-mask loads) on
baked-direct world receivers: baked-only lights keep their exact diffuse in the stored carriers, realtime-weighted
lights keep their specular in the main loop. This matches retail L4D2 world surfaces (envmaps only). The loop
walks every live receiver entry of the pixel's face; in light-dense rooms it cost about 7 ms on a GTX 1050
(c1m1 corridor, measured by toggling the cvar in one process, so up to ~1 ms of that is the toggle penalty
described below) while each entry's view index was still a binary search. With one `PBR_ViewLightIndex` load
per entry it costs 3.4 ms there (world pass 8.0 ms at 0, 11.4 ms at 1, separate launches). A
member-driven variant (binary search per tile member instead of per entry) was tried under the same toggle
method and dropped: -1.2 ms in the corridor, +3 ms on the roof.

While it is 1, world local-light specular is capped per tile by `r_world_local_specular` (archived, default 4,
range 1-4; 0 = every light, the reference). While building each view's tile CSR, the client ranks
every light of a tile by its unshadowed radiance (attenuation/cap, spot cone and fade, as in
`TileSpecularScore`) at the point of the tile-centre ray closest to the light, and publishes the
top-4 view-light indices per tile (`tileSpecular` in the view packet, `g_ShadowTileSpecular`
t1035 space2). `PBR_GatherDirect` evaluates the local-light specular lobe only for lights in the
receiver tile's list; diffuse (including every baked delta) is evaluated for all lights exactly as
before, and skipped specular is dropped, not folded. Selection is per tile on the CPU, never
per-pixel in the shader (a per-pixel candidate pool measured 3-5 ms *slower* from register
spills). Interface `ShaderAPIDX12Lighting_013` added the packet field and table slot; both shader
validators (`shader_precache_dx12`, `nativeshaderpack_dx12`) know the t1035 binding.
The ranking is tiles x lights on the main thread for every world view (42% of the frame's CPU time in the
c1m1 corridor, which capped it at ~50 fps), so it runs only while `r_world_baked_specular` is 1: at 0 the
client publishes the neutral list, the material sends cap 0 (c40.x) and the shader loads no tile list (main
thread there: about 18 ms to under 10 ms per frame, from xperf samples over frames rendered). The
cap was only ever needed for the baked-only loop; the few realtime-weighted lights of the main loop always
keep their specular. The ranking itself reads a compact per-view copy of the ranked fields
(`TileSpecularLight_t`) instead of the 608-byte light records, and skips viewmodel views.

Timing changes in these shaders (GTX 1050): changing, inside a running process, any pixel-shader constant the
world shader branches on made the opaque world pass 0.9-1.2 ms slower at once, and normal again the moment the
old value returned. That included a constant bit that selects nothing and `r_world_local_specular 3` instead of
4; a component the shader does not read had no effect, and launching with the changed value in place showed no
penalty (7.98 vs 8.11 ms). The cause is below this code (the same shader and draw stream ran in both states),
so a cvar A/B inside one process charges that penalty to whichever state is not the one the process started
with. Compare two states that both differ from the start state, or separate launches, and repeat them: two
identical launches minutes apart differed by 0.7 ms on this pass while other desktop processes held 8-10% of the GPU.

`mat_pbr_showgbuffer 1|2|3` (cheat) shows normals, F0 or roughness of the opaque scene.

### PBR G-buffer contract

The opaque main view (`VIEW_MAIN`, mono, not cubemap capture; `INT_RENDERPARM_DX12_PBR_GBUFFER_PASS` BEGIN/END around
`DrawWorld` + `DrawOpaqueRenderables`) keeps two scene-sized, scene-multisampled targets next to scene color. Viewmodel,
3D sky, water, monitors and cubemap capture do not. Every PBR pixel shader (`PBR_Output`) writes the targets. Consumers
read sample 0 through `DX12MaterialPbrNormals()` / `DX12MaterialPbrSpecular()`, and validity through
`DX12MaterialSceneStencil()`:

| Target | Format | Content |
|---|---|---|
| normals | `R16G16_UNORM` | world-space shading normal, `PBR_PackNormal( N )` (octahedral coordinates in [0,1], `pbr_oct.hlsli`) |
| specular | `R8G8B8A8_UNORM` | `F0.rgb`, roughness in alpha |
| stencil | scene `D24S8`, bit `0x80` | set on a PBR depth write, cleared by any other depth-writing draw in the pass |
| environment (SSR brackets only) | `R16G16B16A16_FLOAT` | `E.rgb`, the cubemap term in final scene units; alpha `D`, the specular-luminance-weighted light distance of the direct specular (sun 60000, 0 when it is zero) |
| response (SSR brackets only) | `R16G16B16A16_FLOAT` | `K.rgb`, what a sampled scene radiance is multiplied by to replace `E`; alpha 1 for a fresh eligible writer |
| direct specular (SSR brackets only) | `R16G16B16A16_FLOAT` | `S.rgb`, the direct GGX specular (sun, shadowmap locals, projected spots, draw-local lights) in final scene units; `ssr_composite_cs51` subtracts `O * S`, `O` the confidence-weighted soft `[hitDistance < D]` |

- **A pixel holds PBR data only while stencil bit `0x80` is set.** The backend forces that bit on every depth-writing draw
  inside the pass. Consumers read the stencil plane (`X24_TYPELESS_G8_UINT`, plane 1) as `Texture2D<uint2>` /
  `Texture2DMS<uint2>` and test `.y & 0x80`, sample 0 under MSAA. A legacy draw does not write the colour targets, so a
  nearer legacy surface used to leave stale PBR data; it now clears the bit. Blended draws do not write depth and leave
  it. `pbr_gbuffer_debug_cs51` is the reference consumer.
- The pass does not clear the colour targets, and `specular.a == 0` is not a validity test.
- Translucent draws are outside the pass. Outside the main view the targets are not attached.

### GTAO temporal accumulation

`gtao_main_cs51` and the optional spatial denoise passes produce a deliberately
animated low-sample XeGTAO term. `gtao_temporal_cs51` then reprojects that term
through the current frame's motion vectors (or the previous view-projection when
motion vectors are unavailable). Accepted history is reconstructed from a
depth-weighted bilinear 2x2 footprint, rejects out-of-bounds and
view-depth-disoccluded taps, and clamps the result to the current 3x3 AO
neighbourhood before applying a default 0.93 history weight. The history and its
view-depth guard are ping-ponged at the AO working resolution, so the accumulation
is reset on a camera cut, level initialization, target resize, or disabled `r_gtao_temporal`.

`r_gtao_temporal 0` selects the pre-temporal term. `r_gtao_temporal_weight`
controls the accepted-history blend from 0.5 to 0.98 (default 0.93); it is
intentionally not exposed in the Graphics tab because it is a debugging/tuning
control rather than a quality tier. The final temporal output remains the term
published to SSR, preserving AO on both receivers and reflected hits.

### Screen-space reflections

`shaderapidx12/screenspace_ssr_dx12.cpp` runs stochastic SSR on single-sample scenes (MSAA scenes skip it) over the
receivers above, every roughness included; misses and low-confidence pixels keep the cubemap term `E`.

SSR payload writes remain RGBA16F, with no precision reduction. While a bracket captures SSR, non-envmapped
PBR materials suppress the E+D and direct-specular MRT writes but still write K+valid as zero. Existing response
alpha rejection makes retained E/D/S behind those pixels unread, including the trace's hit-normal guard.
This reduces their total scene/G-buffer writes from 40 to 24 bytes per shaded fragment (16 bytes saved);
envmapped writers retain all six outputs. Outside SSR capture (including `r_ssr 0`) the three payload targets
are not attached, so the base scene/normal/F0 writes remain 16 bytes per fragment.

`r_ssr_quality 0/1/2` retains the 24/48/96-step quality profiles and their half/half/full trace sizes (default 1).
Archived `r_ssr_resolution` scales that profile's trace size independently on both axes: 1 is the original output,
0.5 traces one quarter as many texels, and 0.25 one sixteenth. At balanced quality and 1080p these are
960x540, 480x270 and 240x135. Ray steps, refinements, roughness/cone filtering, neighbour-ray count and temporal
history lengths do not change. The resolve and its auxiliary target scale to the full viewport times `r_ssr_resolution`; the
composite and history remain full resolution. At reduced settings the composite selects among adjacent resolve texels using
the receiver's full-resolution depth and normal, rejecting discontinuities before applying the temporal filter. The scene
capture and colour mip chain remain full resolution so the reflected radiance cone and default path stay unchanged.

| Pass | Size | Output |
|---|---|---|
| `ssr_depth_cs51` | viewport | positive view depth; ping-ponged so the composite validates history against the previous frame |
| `ssr_reduce_color_cs51` | mip chain | mean-colour mips of the scene copy |
| `ssr_trace_cs51` | profile (half/full) times `r_ssr_resolution` | one GGX visible-normal sample (Heitz 2018) per texel from a pixel rotating through its full-resolution cell each frame (legacy 2x2 rotation at scale 1); radiance + confidence, and the ray `( hit, +pdf )` / `( direction, -pdf )`. The colour mip is the sample's filtered-importance cone; the hit radiance is multiplied by the frame's GTAO term at the hit (`SetAmbientOcclusionTerm`), because the scene copy precedes the GTAO apply |
| `ssr_resolve_cs51` | full viewport times `r_ssr_resolution` | reduced settings compute one receiver-centred GGX ray reuse result per resolve texel; full-resolution composite selects depth/normal-compatible neighbours; at 1 this is the original viewport dispatch and exact ray reuse |
| `ssr_composite_cs51` | viewport | temporal filter: history reprojected through motion vectors (or the previous camera) for rough lobes and the reflected virtual point for glossy ones, depth-validated, clipped toward the mean of the resolve's 3x3 neighbourhood at trace spacing (mean +- 1..2 sigma, wider when rough); current weight `1 / n` with a per-pixel history length `n` capped at 8 (glossy) .. 32 (rough) frames; writes the next history `C`, `( O, n )` and `delta = C.rgb * K - C.a * E - O * S` |

History is dropped after a skipped/failed frame, a viewport change or a recreated target. The noise sequence advances
with the frame counter so the temporal upscaler integrates what the SSR history leaves.

GTAO is split around SSR: its term is computed after the motion vectors and before `DispatchSSR` (the main and final
denoise passes publish it through `IShaderAPIDX12Compute::SetAmbientOcclusionTerm`), and applied after SSR's
correction, so receivers and reflected hits both carry AO.

## Verification

`shaderapidx12_smoke -case nativeparity` renders every `# pair` twice — native VCS vs the SDK's DX9 VCS through the
legacy translator — with identical inputs (deterministic material blocks, engine ambient/lights/fog commits,
TEXCOORD0..7, linear-filtered textures) and fails on any channel difference above 2/255. `-case all` includes it.

Differences from the DX9 source that exist because the shipped VCS was built by a D3DX9 compiler with different
arithmetic are reproduced in the generators, not in hand-edited HLSL (`gensource.PATCHES`, `gencommon`):
`rsq(0) = FLT_MAX` (`DX12Rsq`/`DX12Normalize`), `sqrt` as `rcp(rsq)` in core and eye_refract, tree sway and vortwarp
sine polynomials/range reduction, the water radial-fog register alias, and color_projection's scalar select.

`worldtwotextureblend` ports the **older shipped shader**, not the repository's newer radial-fog variant, and
participates in nativeparity. `gensource.ABI_PATCHES` restricts `PIXELFOGTYPE` to `0..1`: the dynamic multipliers are
water-alpha 1, pixel-fog 2, depth-alpha 4, and flashlight-shadows 8 (16 dynamics, 24,576 total combinations).
The same directive override generates `legacy_reference/worldtwotextureblend_ps2x.fxc`; the build compiles that
copy with `ShaderCompile2 -dynamic` and retains the packer's strict range/order/multiplier/skip comparison.
Seven representative shipped VCS payloads (plain, height fog, detail, detail-alpha-mask, diffuse bump, flashlight,
and flashlight shadows) matched current-source fxc arithmetic apart from compiler scheduling; no additional
material-specific arithmetic patch was needed.

The shipped DX9 DLL still calls `GetPixelFogCombo1(true)`, although its VCS has no radial-fog combo: radial value 2
collides with the depth-alpha bit in its older index arithmetic. Native C++ uses `GetPixelFogCombo()` to select
only supported none/height fog, keeping the independent depth/shadow bits and all indices within the 16-combo ABI.
Parity constraints inferred from material C++ are limited to combos actually declared by both generated stages;
the obsolete VS `FLASHLIGHT` setting must not reject every WorldTwoTextureBlend pair.

## Post-composite producer gates

`DX12_PostFXComposite` exposes integer `$bloomenabled`, `$flareenabled` and `$glareenabled`.
`SHADER_INIT_PARAMS` explicitly initializes each omitted/undefined gate to 1 via
`SET_PARAM_INT_IF_NOT_DEFINED`; `SHADER_PARAM` declaration defaults alone are insufficient for
runtime-created materials. Explicit zero remains zero, while isolated/baseline materials that
omit the new gates preserve the existing producer path.
The client may disable producers only under the finite-HDR intermediate contract when their
terms have zero weight and no corresponding debug output requires them. Disabled textures bind
standard black. Bloom also sets `gOutput.y` flag 8, bypassing its explicit mip-1 `Load` sequence:
the one-mip standard-black texture must never be queried at mip 1. Enabled sampling and composite,
AgX, LUT, noise and output arithmetic are unchanged. Client demand/consumer gates live in
`game/client/postprocess_dx12.cpp`; the capture owner must verify their pixel and timing behavior.

## Layered bloom (MagicBloom on the compute pyramid)

`postfx_downsample_cs51` `THRESHOLD 2` builds the first bloom level from the exposed scene with MagicBloom's soft
threshold per tap, `c * clamp( luma601( c ) - t, 0, b )` with `t = mat_postfx_bloom_threshold` (default 1.25; MagicBloom uses 1) and the extraction boost cap `b = mat_postfx_bloom_boost` (default 0.015; MagicBloom uses 10, passed as `p2`), and writes the plain exposed level to `u1` for the lens
flare (one pass feeds both chains). `postfx_upsample_cs51` sums layers instead of lerping: `up[last] = down[last]`,
`up[n] = down[n] + tent3x3( up[n + 1] )`, so bloom mip 1 holds every layer; a dropped fine mip (lower
`mat_postfx_bloom_quality`) passes `p0 = 0` and only carries the sum up. The client divides
`mat_postfx_bloom_intensity` (bloom exposure, MagicBloom's 100) by the summed layer count and the composite computes
`bloomT = Uncharted2( bloom * exposure ) / Uncharted2( 11.2 )` (A 0.15, B 0.5, C 0.1, D 0.2, E 0.02, F 0.3), then
`bloomT = screen( bloomT, dirt * bloomT )`. Lens flare and glare are added to the HDR scene at
`mat_postfx_lensflare * 0.1` before AgX; the output is `peak * screen( AgX( scene ) / peak, saturate( bloomT ) )`
ahead of the LUT, dither and HDR scale. Debug view 1 shows `bloomT`.

## Exact glare reach bound

`DX12_PostFX` pass 8 (`postfx_glare_cs51` `REDUCE 1`) reduces the glare input to
componentwise RGB maxima in a fixed 16x16 FP16 target, then to its 1x1 mip 4.
Each group covers a disjoint integer source rectangle, so odd dimensions and
all edge texels are included. Maxima of FP16 source channels remain exactly
representable; storing a summed luminance in FP16 instead could round the bound
down. Glare pass 6 binds that 1x1 maximum at SRV 1. Its RGB sum conservatively
bounds any bilinear-clamped source sample, and the source screen mask is at most
one. With a small FP32 rounding guard on the bound only, the gather stops when
the remaining distances exceed every possible source half-length (or emits zero
when no sample can exceed the 0.1 luminance threshold). Original tap spacing,
retained sample/contribution arithmetic and accumulation order are unchanged.
The two reductions run only when glare is demanded, including `mat_postfx_debug 3`.

## Render scale and adapter tier

`r_upscaler_scale` (default 1 = native; opt-in 0.77 / 0.667 / 0.58 / 0.5, never set by a preset) shrinks the main 3D viewport the way `mat_viewportscale` does
(`view.cpp`); the temporal upscaler (`r_upscaler` modes 1-4: auto / DLSS / FSR / XeSS) then reconstructs the unscaled frame.
Mode 5 selects vendor-independent, native-resolution **SMAA T2x**, combining two-phase jitter with an HDR temporal resolve.
SMAA T2x ignores `r_upscaler_scale` without changing its saved value; the backend rejects scaled SMAA T2x inputs.
Auto remains provider-only (DLSS / FSR / XeSS), never SMAA T2x.
`r_upscaler_lod_bias` (archived, default -1) controls material texture sharpness without disabling mipmaps.
The separate archived `r_upscaler_lod_bias_auto` defaults to 1 so -1 remains an unambiguous explicit value:
auto 1 uses `log2(renderWidth / displayWidth) - 1` for DLSS/DLAA, FSR and XeSS (-1 at native, -2 at half scale),
and -0.5 for native SMAA T2x. Auto 0 uses the explicit `r_upscaler_lod_bias` in [-2, 0]; use
`r_upscaler_lod_bias_auto 0; r_upscaler_lod_bias 0` for the unbiased texture comparison. Temporal AA off always
adds zero bias. The client submits the effective view bias before the first material draw through
`FLOAT_RENDERPARM_DX12_UPSCALE_LOD_BIAS`; the backend applies it only after selecting an available temporal provider.
Only mipmapped world/model material textures receive the additive bias (per-texture `TexLodBias` is retained).
Render/depth targets, screen-space/post resources, lightmaps and highres lightmap pages, cubemaps/IBL and UI/VGUI
stay unbiased. The material group guard also protects UI draws that reuse a world texture. Sampler descriptors
and prepared texture keys are invalidated/re-keyed only when the bias changes; there is no per-frame sampler rebuild.


The SMAA path uses the MIT-licensed iryoku/smaa area/search tables and morphological searches (`thirdparty/smaa`),
perceptual HDR luma edges, YCoCg variance/history clipping, motion/depth rejection and Karis-weighted temporal blending.
History resets on cuts, missing frames and feature rebuilds; mild sharpening is output-only. Animated screen-space
dither uses the same positive temporal status as provider AA. `r_upscaler_status` (with `sv_cheats 1`) prints the
runtime status: SMAA T2x active is 1025 (`1 | (4 << 8)`). The `Temporal AA` GPU event measures the complete AA/copy
envelope for all modes, including any explicitly enabled DLSS-NR layers.

The client submits the render size as `FLOAT_RENDERPARM_DX12_UPSCALE_RENDER_WIDTH/HEIGHT` with every dispatch; the backend reads
colour, depth and motion vectors from the top-left render rectangle of the scene-sized targets and writes a scene-sized
output (a record-time rejection bilinear-stretches the rectangle instead). After the dispatch `CViewRender::RenderView`
switches to the unscaled viewport, so velocity blur, overlays, post-processing and the HUD run at full resolution;
`motion_blur_mv_ps51` reads velocities through `$velocityregion` (the 3D render size). DLSS-NR runs only at native scale,
and frame generation keeps the native render size. A scale whose provider feature fails is dropped (native) until
`r_upscaler` or `r_upscaler_scale` changes.

`IShaderAPIDX12::AdapterPerformanceTier` classifies the adapter at device creation: integrated/UMA, software, under
~6 GB, or without mesh shaders or DXR 1.1 (Pascal, Maxwell, GTX 16, RDNA1) is low. On the first level load for a new
adapter (`r_quality_tier_adapter` records it) a low-tier adapter gets the low preset in `cdll_client_int.cpp`
(`ApplyAdapterQualityTier`, native resolution: SMAA T2x anti-aliasing (`r_upscaler 5`), quarter-resolution 8-step
volumetrics stay on, SSR traces at half resolution, low GTAO, PCF sun shadows at low resolution, two realtime local
lights, low bloom and 4-tap motion blur).
High-tier adapters keep the defaults. `-dx12adaptertier 0|1` forces the class.
A config.cfg saved before `mat_postfx_dx12_set` existed gets `mat_postfx_dx12 1` once on the first level load
(`PostProcessDX12_ValidateConfig`); later changes to `mat_postfx_dx12` stick. When the post stack cannot create its
render targets or materials, the console says so and the legacy engine post runs.

Swap chains always have three flip buffers (`mat_triplebuffered` is ignored): with two, a vsynced frame that misses a
vblank stalls the queue on the back-buffer copy, so the frame rate snaps to 60/30.
Texture filtering offers anisotropic 4x, 8x and 16x only (`vgui_graphics_options.cpp`): a global cvar change callback
snaps `mat_forceaniso` to the nearest offered level at or below its value (below 4 becomes 4) and keeps
`mat_trilinear` at 0, whether the value comes from config.cfg at boot, the console or the stock video page.

Upload pages (`pipeline_dx12.cpp`) use cached write-back memory only on cache-coherent UMA adapters and the
write-combined upload heap elsewhere; `-dx12uploadwb` forces the write-back pages for A/B comparisons.
Idle upload pages are released only after their retirement fence completes and remain idle for 120 renderer frames. The pool retains at least four pages, plus every recent or in-flight page; active pages are
never relocated or copied. The upload line in `-dx12stats` reports per-window aligned demand, peak frame demand,
page creations/trims and current pool buffer bytes, so a steady scene should show `newPages 0` after load-time bursts.


Per-pass GPU times: launch with `-dx12stats -dx12statsframes 300 -condebug`; every 300 frames the console log lists the
GPU frame time and each PIX event's ms/frame. For a live compact view, set `cl_showfps 3`: the normal FPS line is followed
by the latest approximately 0.5-second inclusive GPU pass timings, emitted in tree order (nested passes are indented),
plus GPU and CPU frame milliseconds. The overlay's timing queries and readbacks stay disabled while `cl_showfps` is below
3 (apart from explicitly requested `-dx12stats` captures), so mode 0 adds no overlay timing-collection work. Event timestamps
use one batched resolve per submitted command list; the remaining cost is GPU-dependent. A representative 1080p RTX 4070S
capture measured about 0.2 ms (6%) of additional GPU time with mode 3.

## Native resource memory

`sv_cheats 1; dx12_memreport` queues one allocation snapshot at the next render-owner Present. Repeated pending
requests coalesce. The first `-dx12stats` window also includes this report, so the standard GPU statistics log records
the initialized renderer without continuous memory-report overhead.

The snapshot lists every tracked live renderer-created committed/placed resource, including allocations retained by
an incomplete fence. It groups counts and bytes by subsystem and textures by DXGI format; sizes come from
`GetResourceAllocationInfo`, not width-times-height estimates. The selected adapter's DXGI LOCAL and NON_LOCAL
process usage/budget are separate: allocation totals are not residency, placed-resource ranges can overlap, and swap
chains, driver storage and external provider allocations are not included in the tracked-resource total.

The memory reductions preserve formats and working pixels:

- Single-sample motion rasterizes directly into its compatible engine RGBA16F target and avoids the extra private
  allocation and full-target copy. MSAA retains its private multisample target and resolve. Append/viewmodel retargets,
  UAV promotion and deletion keep their existing accumulated contents and canonical resource states.
- SSR reuses the captured scene's mip 0 for its signed RGBA16F delta after trace, the final reader of that scene copy.
  Resolve and temporal accumulation do not read it; the additive composite and the next frame's capture remain unchanged.
- GTAO edges and motion-blur classification tiles allocate their declared working dimensions and are fully overwritten
  before any bounded read. GTAO depth and AO term targets retain their original physical sizes: depth mip rounding and
  SSR's linear AO border samples depend on those sizes.
