# stdshader_dx12 — native SM5.1 material shaders for shaderapidx12

`stdshader_dx12.dll` is the material shader DLL the DX12 backend selects (`CHardwareConfigDX12::GetShaderDLLName()`).
It registers the same material names, parameters and combo semantics as the DX9 `stdshader_dx9`, but draws with
precompiled SM5.1 DXBC shaders published as VCS files in `<game>/shaders/vsh`, `<game>/shaders/psh`, and
`<game>/shaders/csh`.

## Layout

| Path | Content |
|---|---|
| `cpp/` | Material C++ (ported from `materialsystem/stdshaders`) and `BaseVSShaderDX12.*` (constant staging, native block selection, command-buffer execution). Hand-maintained. |
| `hlsl/` | Generated native sources `<base>_vs51.fxc` / `<base>_ps51.fxc`; `hlsl/common/` shared headers. **Generated** by `tools/` — never edit by hand. |
| `native_src/` | Hand-authored native-only SM5.1 sources, including compute (`*_cs51.fxc`). These are the single source of truth and are compiled directly; they are never copied into generated `hlsl/`. |
| `manifests/` | Per-slice build manifests (`<source> <vs\|ps\|cs> <logical> <legacy profile> <legacy source>`, where native-only uses `native -`, plus `# pair`, `# noparity`, `# legacy`). Generated by `tools/genmat.py`. |
| `legacy_reference/` | Generated DX9 source copies with shipped combo-directive overrides (`gensource.ABI_PATCHES`). Used only for legacy-backed packer `-dynamic` ABI references; original SDK sources are unchanged. |
| `generated/` | Combo index includes, cbuffer C++ layouts, reflection metadata. Written by `nativeshaderpack_dx12` on every build. |
| `tools/` | Generators: `gencommon.py` (hlsl/common from the DX9 headers), `gensource.py` (per-source conversion + `PATCHES` for shipped-compiler quirks), `genmat.py` + `pairs.py` (pair table → hlsl + manifests), `hlslport.py` (sampler/intrinsic translation), `quickcheck.py` (sampled fxc compile of every source). |
| `vpc/`, `stdshader_dx12.vpc` | DLL project. |

## Naming

Native logicals are `<base>_vs51` / `<base>_ps51`, one per base. Compute logicals are native-only `<base>_cs51` and
are published under `shaders/csh`; they have no DX9 record or fallback. Legacy-backed logicals also name a DX9 record
(`<base>_vs20`, `_ps20b`, `_vs30`, …) used for the combo-ABI reference and fallback record in `shaders/fxc`.
Material C++ uses the `_vs51`/`_ps51` index classes; names that come from VMTs (`screenspace_general`'s `$pixshader`,
`sample4x4`, `floattoscreen`) are mapped with `DX12NativeShaderName()`.

## Build

```bat
cd /d src\materialsystem\stdshaders_dx12\tools
python gencommon.py        :: only when common headers / hlslport change
python genmat.py
python quickcheck.py       :: optional sampled compile check
cd /d src
devtools\bin\buildshaders_dx12.bat -game <gamedir>   :: or -stage <tempdir>
```

`buildshaders_dx12.bat` → `process_shaders.ps1 -Native`: compiles each manifest line with `ShaderCompile2 -ver 51`
(rebuilt from `thirdparty/ShaderCompile2`; bounded memory, memory-aware threading) in a persistent per-logical cache.
Generated `hlsl/` and hand-authored `native_src/` sources are both available to the compiler; native-only lines are
compiled directly and are not copied into generated trees. Legacy-backed lines additionally compile their DX9 source
with `-dynamic` (using `legacy_reference/` overrides where present), then `nativeshaderpack_dx12` validates DXBC,
VCS v6, cbuffer reflection/space-1 rules, and combo ABI only where a legacy reference exists. It owns `shaders/vsh|psh|csh`
entries listed in `shaders/native_dx12_published.txt` and writes `shaders/native_dx12_legacy_names.txt`; nothing is
written under `shaders/fxc`. Build cost depends on the manifest set, folded combo counts and compiler-cache state. Then rebuild
`stdshader_dx12` (it includes `generated/`).

## Runtime contract

- Material constants keep the DX9 register vocabulary and are staged in the DLL; each selected native block is sent
  once per draw through the private space-1 cbuffer bridge (`native_cbuffer_dx12.h`). Engine values (matrices, fog,
  ambient cube, lights, bones) come from the backend's engine blocks.
- A legacy-backed native logical whose `shaders/vsh|psh` record is absent resolves to its legacy DX9 record in
  `shaders/fxc` via `native_dx12_legacy_names.txt` and is translated as before.
- Native-only logicals have no legacy name or fallback. Their native VCS must exist at runtime; if it is missing,
  the backend fails the shader load rather than trying `shaders/fxc`.
  SM2/SM3 centroid interpolation is declared in the VCS header (centroid mask), not in the bytecode; the backend
  carries that mask to the legacy translator, matching the native sources' `centroid` inputs.
- `-dx12shaderlog` prints which VCS file each named shader was loaded from.
- `shader_precache <logical> [static] [dynamic] | all` (cheat) validates/reflects published VCS payloads on the render
  thread; it never writes VCS files.
- Legacy VCS centroid masks are carried into deferred translation. SM2 shaders declare centroid TEXCOORDs in
  the VCS header rather than bytecode DCLs; dropping that mask makes MSAA edge inputs differ from native shaders.

## Explicit high-resolution BSP replacement

`tools/genhighres.py` catalogs actual RGB lightmap consumers: LightmappedGeneric/WorldVertexTransition,
WorldTwoTextureBlend, LightmappedReflective, the bumped decal pass, Water's base-texture pass,
ShatteredGlass, and PyroVision's world-lightmapped effects. `genmat.py` independently emits their
`*_highres_vs51`/`*_highres_ps51` twins alongside ordinary and old `*_shadowmap_*` shaders.
The decal self-illumination second pass samples only its base texture; cheap water/refraction-only passes
do not consume BSP irradiance. WorldVertexAlpha's DX9 draw is unreachable through its DX8 fallback;
DX8 fixed-function consumers are backend paths. The actual WorldVertexTransition editor assembly pass
uses authored `worldvertextransition_editor_highres_*` native replacements on enhanced maps, retaining its
texture transforms, two-material vertex-alpha blend and original sampled lightmap alpha.

The original base UV is carried before bump shifts, with no inverse-coordinate carrier input.
`native_src/highres_lightmaps.hlsli` translates the integer owner atlas into explicit face/style/plane tiles,
adds captured native dynamic planes, and preserves native sampled alpha. Material lighting retains its
existing bump/SSBump weights, two-material blend, tint and fog/output ordering; selected direct lighting
is gathered once and only selected sunlight is capped by the designated style-0/base alpha.
Brush sun capping requires an explicit baked model pose equal to the draw transform.
An unknown owner or malformed shader-side address sets `HlightFailure` (`u0 space3`); it is not a
white/unmasked fallback.
A known neutral `route.enabled=0` preserves native RGB/alpha, native normalization and the selected-direct
gather; an invalid owner with `route.enabled=1` contributes neither baked RGB nor selected direct while
the real GPU failure is reported. Neutral metadata-only maps are not mistaken for malformed owners.

The packer publishes `<logical>.hlight` beside each participating VCS: four little-endian uint32 words
`{0x544c484e, 1, lightmapSamplerMask, highresAbi}`. Ordinary/old variants carry original sampler roles;
highres vertex variants carry mask zero and ABI one. Roles include reflective/water sampler 3 and decal
samplers 1/2/3. The backend selects matching highres variants from this metadata, not material names.
The packer also emits `generated/inc/highres_lightmaps_hlsl.inc` and `shadowmap_lighting_hlsl.inc` for
backend-owned fixed-function compilation without an include handler.
Lighting interface `_004` copies explicit native generation/route and all 64 view-consistent lightstyles;
the separate highres draw cbuffer is 320 bytes (`route`, three model rows, sixteen packed style rows).
After generator changes run `gencommon.py`, `genmat.py`, rebuild/publish with the updated native packer,
then rebuild both backend and material DLL against the regenerated includes.

### Baking an enhanced map

After VBSP/VVIS, run from `src` (PowerShell), using a game directory that resolves the map's assets:

```powershell
& ..\game\bin\x64\vrad_restir.exe `
  -game ..\game\mod_episodic `
  -restir_shadowmaps -restir_hlight_density 4 `
  -final -restir_iterations 128 -restir_seed 1 -restir_denoiser none `
  "F:\path\to\map.bsp"
```

The versioned `.hlight` asset is embedded in the BSP pak; deploy the BSP, not a separately named loose file.
The native BSP lightmap grid stays unchanged (`-restir_lightmapscale 1`, the default).
Density 1 uses native-resolution sampling; density 2 and 4 independently bake approximately 4 and 16 times
as many surface sample locations, respectively. Density changes neither iteration count nor bounce count.
`-restir_shadowmaps` currently forces paired LDR/HDR baking and enables static-prop lighting/texture shadows,
even with `-hdr`. Runtime HDR-first selection does not yet eliminate that second bake.

Without a preset, quality is 128 iterations, 8 local-light candidates, 4 maximum bounces and balanced OIDN.
Bare `-final` selects 512 iterations, 16 candidates, 6 bounces and high-quality OIDN.
The command above explicitly overrides final iterations to 128 and disables denoising; explicit options
win regardless of argument order. `-fast` selects 32 iterations, 4 candidates, 2 bounces and fast OIDN.

The renderer reports Source material tier **110**, distinct from its D3D12 API and minimum device feature
level 11_0. It enforces `mat_dxlevel=110` and `mat_hdr_level>=2`: HDR-capable maps use HDR lighting,
while genuine LDR-only maps retain the engine's LDR fallback. HDR monitor output is a separate setting.
Legacy enhanced manifest v3 maps require a rebake; the abandoned inverse-addressing path is not a fallback.


## Native-only shaders

Native-only is reserved for DX12 shaders with no meaningful DX9 implementation or combo-ABI reference. Register one
with `native_only(...)` in `tools/pairs.py`; `genmat.py` emits `<source> <vs|ps|cs> <logical> native -` and the source
must live in `native_src/`. The packer still enforces DXBC stage/VCS version, combo-count sanity, cbuffer reflection,
space-1 declarations and native cbuffer registry generation, but performs no legacy compile or parity comparison.
The runtime has no legacy fallback for these logicals, so the published native VCS is required.

## Compute shaders

Compute manifests use the same native-only form with a `cs` stage:

```text
gtao_main_cs51.fxc cs gtao_main_cs51 native -
```

`process_shaders.ps1 -Native` compiles this with `ShaderCompile2 -ver 51`, which derives the `cs_5_1` profile,
emits the VCS v6 combo table and a normal `<logical>_Static_Index` / `<logical>_Dynamic_Index` include, and passes
both artifacts to `nativeshaderpack_dx12`. The packer validates a compute DXBC program, requires `b0 space1` for
the constants cbuffer and `t*`, `u*`, `s*` resources in space 0, then publishes
`<game>/shaders/csh/<logical>.vcs` and records it in `native_dx12_published.txt`.

Compute includes intentionally contain no graphics native-cbuffer block writer. Material C++ passes the reflected
`b0` bytes directly through `IShaderAPIDX12Compute::Dispatch`, binds SRV/UAV resources to the generic root signature,
and calls `Draw( false )` for material bookkeeping. The runtime loader opens `VcsStage::Compute`, which reads from
`shaders/csh/` and rejects non-compute DXBC.

## Verification

`shaderapidx12_smoke -case nativeparity` renders every `# pair` twice — native VCS vs the SDK's DX9 VCS through the
legacy translator — with identical inputs (deterministic material blocks, engine ambient/lights/fog commits,
TEXCOORD0..7, linear-filtered textures) and fails on any channel difference above 2/255. `-case all` includes it.

Differences from the DX9 source that exist because the shipped VCS was built by a D3DX9 compiler with different
arithmetic are reproduced in the generators, not in hand-edited HLSL (`gensource.PATCHES`, `gencommon`):
`rsq(0) = FLT_MAX` (`DX12Rsq`/`DX12Normalize`), `sqrt` as `rcp(rsq)` in core and eye_refract, tree sway and vortwarp
sine polynomials/range reduction, the water radial-fog register alias, and color_projection's scalar select.

`worldtwotextureblend` ports the **older shipped shader**, not the repository's newer radial-fog variant, and
participates in nativeparity. `gensource.ABI_PATCHES` restricts `PIXELFOGTYPE` to `0..1`: the dynamic multipliers are
water-alpha 1, pixel-fog 2, depth-alpha 4, and flashlight-shadows 8 (16 dynamics, 24,576 total combinations).
The same directive override generates `legacy_reference/worldtwotextureblend_ps2x.fxc`; the build compiles that
copy with `ShaderCompile2 -dynamic` and retains the packer's strict range/order/multiplier/skip comparison.
Seven representative shipped VCS payloads (plain, height fog, detail, detail-alpha-mask, diffuse bump, flashlight,
and flashlight shadows) matched current-source fxc arithmetic apart from compiler scheduling; no additional
material-specific arithmetic patch was needed.

The shipped DX9 DLL still calls `GetPixelFogCombo1(true)`, although its VCS has no radial-fog combo: radial value 2
collides with the depth-alpha bit in its older index arithmetic. Native C++ uses `GetPixelFogCombo()` to select
only supported none/height fog, keeping the independent depth/shadow bits and all indices within the 16-combo ABI.
Parity constraints inferred from material C++ are limited to combos actually declared by both generated stages;
the obsolete VS `FLASHLIGHT` setting must not reject every WorldTwoTextureBlend pair.
